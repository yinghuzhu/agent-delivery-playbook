# 页面测试复用与并行：权威用例 v0.1

适用对象：[delivery-workflow](../../../skills/delivery-workflow/SKILL.md)、[交接契约](../../../skills/delivery-workflow/references/handoff-contracts.md)、[acceptance-qa](../../../skills/acceptance-qa/SKILL.md) 和 [通用规则](../../../AGENTS.md)。版本与执行结果见 [审查记录](review-report.md)。

## 公共前置与操作

以下为合成行为案例，仅使用给定材料作出派工与执行决定，不启动浏览器、模型服务或实际测试，不修改业务数据，不提交或安装。除用例另述外，设计和用例已确认、Review 已通过、测试已授权，testing 执行者选择与预算有效。

每例向执行者提供输入及公共边界，要求输出复用/隔离安排、并行/串行分组、资源归属和阻塞项；逐项与预期对照。独立评估时不给执行者预期答案。执行结果另写报告，不写进本文件。

## TR01：默认复用现有环境和数据

- 输入：测试部署环境、原会话和五条现有订单满足列表筛选用例，无写入或共享状态冲突。用户没有要求隔离。
- 预期：说明复用范围和可选隔离，默认直接复用；不创建新环境、重建数据或把隔离确认作为执行门槛。记录现有数据基准与实际待测版本。

## TR02：明确不隔离与数据缺口

- 输入：用户明确不需要隔离。三个用例中两个可使用现有记录，第三个需要一条已取消订单，现有记录均不满足；用户允许新增一条测试订单并按用例取消。
- 预期：复用已有选择，不重复索取隔离确认；前两项正常推进，第三项只补一条所需数据，不重建全套。新增和清理不扩大到其他业务数据，恢复范围明确。

## TR03：必要会话前提无法满足

- 输入：用例要求两个不同身份同时登录以验证授权边界；当前共享登录会覆盖另一身份。用户不希望隔离，目前无可复用的第二个有效会话，也未授权新建会话；其他只读用例无此依赖。
- 预期：说明具体身份冲突及满足用例的最小方案，咨询用户是否调整会话安排；不能因默认复用而降低双身份断言，也不自动创建 profile。用户维持现状时仅该项阻塞，其他用例继续。

## TR04：共享环境中的无冲突并行

- 输入：两个只读用例读取稳定且不同的业务记录，已核对无后台写入、共同可变汇总、登录切换和清理；工具支持不同 Page 并行，现有两个测试执行者与预算足够，任务耗时值得并行。
- 预期：在同一现有环境中并行，不要求先隔离数据；任务单列用例 ID、已核对资源、并行组和各自 Page/执行者，按工具规则管理空间结束。测试者均独立于开发，沿用已有 testing 选择。

## TR05：不同记录的隐含冲突与流程依赖

- 输入 A：两个用例使用不同订单，但都会扣减同一商品库存并断言库存数量。输入 B：三个页面分别执行同一订单的创建、审批和取消。输入 C：两个页面的数据写入范围尚不清楚。
- 预期：A 识别共享库存和断言冲突，B 保留业务步骤顺序，均不能按页面或订单 ID 直接并行；C 补查或先串行。优先有序执行，不强制隔离来提高并发度。

## TR06：读写、清理及运行中干扰

- 输入：用例 A 汇总现有记录，用例 B 修改其中一条，用例 C 完成后拟删除 A 仍需读取的测试夹具。执行期间发现另一任务已改动 A 的基准数据。
- 预期：识别读写和清理依赖，调整顺序，清理后置；发现实际干扰后保留证据并暂停 A 等受影响项，核对新基准及预期，交主 agent 核定复验。不能把被污染结果算通过，不要求无影响用例全量重跑。

## TR07：原状态复现与专门并发用例

- 输入 A：缺陷仅在原登录和旧缓存下出现。输入 B：确认用例要求两个请求按指定屏障同时提交以验证重复扣款，普通页面分组互不冲突。
- 预期：A 保留原会话，不清缓存或从空环境绕过问题；B 按专门时序和断言执行，不能把普通用例随机并行当作并发缺陷测试完成。两者均保持原业务预期。

## TR08：用户选择隔离及测试层级边界

- 输入 A：用户已指定本轮使用现有隔离测试环境和指定数据，不要求重新创建。输入 B：执行自动化 MySQL 集成测试，项目规则要求 Testcontainers；同轮页面验收默认复用现有部署环境。
- 预期：A 沿用已选隔离范围，不以新默认强行复用其他环境，也不重建已有隔离环境。B 保持自动化集成测试的隔离与 Testcontainers 要求，页面验收按其复用安排执行，不混淆测试层级。
