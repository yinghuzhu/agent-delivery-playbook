## 修订依据：浏览器受控实测

执行者为主 agent，通过两个独立 ego-browser CLI 进程模拟并行调用，不是两名独立模型 agent 的行为评估。用户先协调另一执行者暂停，随后明确要求升级并以新版为准。升级前测试空间已清理；实际调用 `ego-browser upgrade`，版本核验为 Ego Lite `0.6.2.8`、Chromium `156.0.8078.74`，运行时指南为 v2.2.0。

2026-11-06 的会话工具回执记录如下。测试使用临时本机 HTTP 服务，端口运行时分配；`localhost` 与 `127.0.0.1` 为不同站点入口，提供可核对记录的表单，不向真实网站提交业务数据。测试空间使用默认 profile。每组独立进程的执行时间区间重叠，结果按页面内容、记录数量、顺序和来源核对。

| 场景 | 实际结果 |
| --- | --- |
| 不同 TaskSpace，同时导航并读取 | 两个页面均返回各自的站点、标题及快照 |
| 不同 TaskSpace，普通输入和点击 | 每边 10 轮，合计 20/20 通过；前 5 轮 fill，后 5 轮清空、点击输入框、keyboard.type，再点击记录按钮 |
| 不同 TaskSpace，同时点击导航链接 | 两边均到达各自预期路径 |
| 同一 TaskSpace，不同 Page | 两边各 10 轮清空、点击、键入及记录，20/20 通过；仅含各自 A/B 标记，顺序和数量一致 |
| 结束另一 TaskSpace 后继续读取 | 保留空间的 12 次检查通过，值与 10 条既有记录不变 |
| 清理 | finish 回执确认两个测试空间关闭，列表仅余既有用户空白空间；临时服务已停止 |

本实验支持上述版本、默认 profile、受控页面和调用方式下的普通交互并发，未观察到串页、串输入或控制权错误；不证明所有网站、版本或更高并发都安全，也未验证完全无可见焦点切换。未覆盖真实账号共同登录、下载并发、原生剪贴板、系统弹窗或多模型自主调度。用户明确说明原任务空间由其主动关闭，不能把该现象归因为升级丢失会话。

运行时指南明确下载使用浏览器共享设置；ego-browser 的 clearing-state 参考明确同 profile 的空间共享 cookies/cache。因此共享资源协调规则不以普通表单实验通过为由取消。
