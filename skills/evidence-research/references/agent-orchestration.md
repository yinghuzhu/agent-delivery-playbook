# 研究子 agent 编排

适用于探索型和目标型研究。主 agent 做调度与裁决，将能独立执行的具体调查交子 agent；单一短问题或强依赖任务可顺序处理。此文规定运行方式，本 skill 不包含常驻调度程序，不会因加载而自动启动任务。

## 执行者与配置

与 delivery-workflow 共用一份默认 `agents.yaml` 及其候选池、首选/备用、进度配置。`selection.search` 配调查 agent，`selection.review` 配独立复核 agent，各自有首选、模型和有序备用；两者是职责选择项，不是模型供应商。执行会话必须不同，不能让调查者复核自己的结果，也不能自动继承对方选择。研究不套用开发前的设计/用例审批阶段。

1. 从当前平台发现真实内置能力；通过当前技能目录或已确认的维护仓库定位 delivery-workflow 的 `agents.yaml` 及 `references/agent-selection.md`，使用其中的配置与合并规则。不假设相邻安装目录、不全盘搜索、不把共享文件复制进本 skill。共享来源有多份时使用本次选定来源并记录版本，不混拼；无法确定时只暂停相关配置选择。
2. 优先级为当前用户明确指令 → 目标项目根 `agent-playbook.yaml` → `${XDG_CONFIG_HOME:-~/.config}/agent-playbook/agents.yaml` 用户配置 → 共用默认配置，按从低到高合并。路径在运行时解析。缺少默认配置时，可使用用户明确指定且内容完整的现有配置作为基线；否则报告依赖缺口，继续无需派工的研究，不另生成默认文件或写死 CLI 名单。发现配置但无法解析时报告错误，不静默当作缺失。
3. `agents` 按 `id` 合并字段，新 ID 扩展，`enabled: false` 禁用；builtin 不可改成 CLI。`selection.search` 与 `selection.review` 分别按字段覆盖：省略继承、null 清除首选、空列表清除备用、非空备用列表整体替换。`primary` 和 `fallback` 项的结构为 `{agent: 候选ID, model: 模型ID}`；首选为空代表未选择，不代表自动选择授权。旧配置缺少哪个角色，哪个角色就视为首选未选、备用为空；不得套用 development/testing 或另一研究角色。用户分别选定相同工具/模型时仍必须新建独立执行会话；用户指定不同工具/模型时严格遵守，不自行合并选择。
4. `models: auto` 表示运行时核对模型，不是 CLI 参数。模型名单、服务可用性和成本均不得猜测。候选表列执行方式、请求模型/服务商、可用性及依据、能力限制、成本是否核实；内置与 CLI 放在同一张表。默认选择满足能力且成本较低的组合；未知价格标未知。
5. CLI 仅按配置命令或用户指定路径查找，读取版本/帮助核对模型、输入、工作目录、输出及权限参数，不自动安装或付费探测。区分已安装、待运行验证、已验证和不可用，以首个获准的实际任务验证服务。`command` 是单个命令名或路径；相对路径按定义它的配置文件解析，用参数数组调用，禁止 eval 或把命令文本当配置执行。
6. 在调查、复核各自首次派工前确定其首选、有序备用或明确自动选择范围及预算。已有各角色授权在本研究内复用；仅声明“可以安排子 agent”不自动确定供应商、型号或预算。尚未选择时继续不依赖该角色的工作，不先启动付费探测；search 已选而 review 未选时可先调查，结果待独立复核，不能让 search 自行代替 review。
7. 校验重复 ID、字段类型、未知/禁用候选引用、显式模型范围等错误；只暂停依赖错误配置的派工。`progress.interval_minutes` 缺省为 10，覆盖值必须是有限正数，布尔、零、负数、无穷或非数均为错误。配置不会自行授予操作权限，也不自动保存用户选择到磁盘。

本 skill 可以单独进行研究；使用配置驱动的子 agent 派工需有可读的共享配置或用户指定的完整替代配置。加载配置不是执行整个 delivery-workflow，也不会触发设计、开发、提交或安装。

## 拆分与并行

主 agent 先固定本轮口径和证据要求，识别依赖后决定并行批次。适合按地域/来源、不同问题群、替代方案、获客渠道或待核结论拆分。行政范围未定但来源入口调查不依赖它时，前者等待裁决，后者继续；不能让每个 agent 自定范围后再合并。

并发不超过实际可用槽位（保留主 agent）、已授权预算、账号/配额和隔离资源能承受的数量，必要时分批。共享文件、账号注册、带计费请求或同一数据操作由主 agent 分配所有者或串行执行；浏览器按下节划分资源。不要为填满槽位重复搜索同一内容；独立复核的有意重复须标明目的。

主 agent 维护一个任务台账，沿用[研究状态入口](research-record.md)，不强制额外文件。每项记录任务 ID、问题、依赖、负责人/会话、请求及实际可核实模型、输出位置、状态、最近证据、阻塞和下一步。状态至少区分待分派、执行中、待核验、待裁决/阻塞、完成、取消；子 agent 返回只进入待核验，不能自动算完成。

## 浏览器并行与资源归属

需要浏览器时读取当前可用浏览器 skill 和运行时说明，核对执行者能否访问分配的资源。已有适用的能力验证可复用，不为每轮派工重复探测；无关版本或其他工具的成功不能作为保证。不强制安装 ego-browser，也不为取证自动升级、重启或切换 profile。能力未明确时只顺序执行依赖该能力的交互，其他取证和分析可继续。

默认以 Page 为操作独占单位，以工具声明的作用域协调共享资源，不把整台浏览器固定为单执行者：

| 资源或动作 | 调度约定 |
| --- | --- |
| 不同 Page 的导航、读取、普通点击与输入 | 工具支持并发且无共享业务状态冲突时可并行；同站点也不自动冲突，不同站点也不自动安全 |
| 同一 Page 的操作与状态读取 | 同时只归一个执行者；交接前完成或停止旧调用，新执行者重新读取页面，不复用可能过期的元素引用 |
| 下载、原生剪贴板及浏览器级设置 | 按实际共享作用域串行；ego-browser 的下载设置由浏览器共享，下载占用从监听与触发一直到保存完成或确认取消，文件输出也须独立 |
| 登录切换、退出、清理存储及共同业务对象 | 按账号、站点、profile 或业务对象的实际影响范围协调；动作仍须有授权，不能仅靠分配不同 Page 消除冲突 |

使用 ego-browser 时，同一用户目标默认沿用一个 TaskSpace，主 agent 创建/复用并给子 agent 分配不同 Page；不同主 agent 的独立目标各自管理自己的 TaskSpace。若子任务需要独立交给用户操作、保留页面或结束，或已核实执行环境不能共享空间，可说明理由，经用户明确同意后拆分 TaskSpace；已有适用于本任务的明确授权直接复用。按任务边界和生命周期划分，不把“每个子 agent 一个 TaskSpace”作为默认隔离办法，不用新空间绕过失控或访问错误。无法共享且尚未获准拆分时，可由有权限的执行者代取证据，说明限制，不接管他人的空间。拆分空间不隔离同 profile 的登录状态、缓存或浏览器共享设置。

派工写明工具、TaskSpace 标识、Page 标签、页面负责人、允许站点/账号范围、共享资源的协调人和证据回传位置；运行标识可在任务消息中交接，不写死在可复用模板中。子 agent 不操作其他任务的 Page，不结束共享 TaskSpace。共享空间由主 agent 收齐结果并确认相关调用停止后，按工具规则统一结束；获准拆分时逐空间指定生命周期负责人、用户交接/保留要求及结束条件，可明确委派子 agent 管理其独立空间，主 agent 核验最终状态。仅清理本任务资源，不因一个子任务完成就关闭其他空间或用户保留的页面。review 使用自己的 Page 和独立执行会话，亲自核对原始来源；浏览器资源隔离不替代证据独立性。

多个主 agent 共用浏览器时，本任务的排队约定不能充当全局互斥锁。涉及跨任务共享资源，须使用已有且所有相关执行者共同遵守的协调机制，或与用户协调其他任务暂停；无法确认互斥时只等待该共享动作，继续不依赖它的工作。本 skill 不实现自动锁，不擅自创建后台锁服务，也不为协调而发送未获准的外部消息。

发生串页、输入错位或控制权错误时，停止受影响交互，核对调用、页面归属和已产生的结果，再决定是否按较大资源范围串行。用户接管、空间 inactive/unassigned 等工具停止信号须遵守，不反复抢回控制或另开空间规避。重新执行前按影响范围检查证据，不把有归属疑问的快照计为已核验证据；恢复或切换执行者前确认旧调用已停止。

## 派工契约与回传

每次交接显式提供，内置和 CLI 相同：

| 内容 | 要求 |
| --- | --- |
| 任务与问题 | 任务 ID、本轮模式、要支持的决定、范围/排除项、完成与停止条件 |
| 已知口径与资料 | 已确认业务规则、证据 ID 和可读路径/版本、已查失败路径、尚未确定事项 |
| 权限与资源 | 允许工具/外部请求、费用与时间约束、可读写范围、账号/会话归属、禁止动作 |
| 浏览器资源（如使用） | 工具与适用能力依据、TaskSpace/Page 归属、共享动作协调方式、交接与结束负责人；跨任务协调未知时明确受阻动作 |
| 协作隔离 | 专属输出目录或只读回传；不同时写公共报告/台账，不跨任务修改文件，不自行再派工 |
| 模型与汇报 | 首选及备用授权、实际执行方式、有效汇报间隔、进度与产物回传位置 |
| 返回契约 | 逐问题结论、原始证据定位、采集/基准时间、覆盖和限制、反证、失败路径、未决项及下一步 |

不假设子 agent 继承历史、自动加载规则或能读取同样的账号资料。模型覆盖与全历史继承互斥时使用独立上下文，显式补齐必要材料。复核者使用另一会话，提供中立问题和原始证据，不要求其证明调查者正确；请求模型和实际可核实模型分别记录，未知如实标注。

获准落盘时，子任务可使用研究目录下 `tasks/<task-id>/`，路径相对该研究目录；未获准落盘时在返回消息提供同等证据定位。任务说明中的时间限制不会自动终止进程，主 agent 须监测并实际停止超时执行。

## 主 agent 核验与裁决

收到回传后，主 agent 检查实际产物、原始出处和目标覆盖，抽查普通证据，对决定性结论直接核对；成功退出码、报告长度和“已完成”不代表验收通过。

- 合并同源证据，记录来源、作者或事件的重叠；多个 agent 同意不等于多个独立来源。
- 对矛盾逐项比较口径、时点、版本、样本和推理链。有明确证据即可在既定口径内裁决，说明取舍，不做多数表决。
- 对关键争议或高影响结论安排已授权的独立复核；未能复核时披露限制，不冒充通过。证据仍不足就保留分歧，不能为了收敛任选答案。
- 缺证、语义不清或工作未完成，退回具体补证任务；业务口径、新范围、额外预算/外部动作由用户裁决，继续不依赖它们的任务。
- 用户修订口径时版本化记录并通知受影响执行者，必要时暂停其动作；复核相关旧证据和正在生成的结果，不允许混合口径。其他无影响任务继续。

主 agent 最终给出结论及依据、未解决问题和下一轮决定，不能仅拼接子报告或把最后判断交给调查者。

## 进度、失败与结束

派工时说明任务、执行方式、模型和汇报间隔，记录开始及最近汇报时间。主 agent 负责向当前用户会话合并汇报已确认成果、当前动作、耗时、最新证据、阻塞及下一步；没有新输出也说明最后已知状态和无输出时长，进程存活不代表进展。

采用可恢复执行和分段等待，等待不得超过下一次汇报期限及平台限制；平台要求更频繁时从其要求。完成、阻塞、失败、切换立即汇报，不等周期。切换执行者不重置整体汇报计时；不能在后台仍运行时结束本轮并假定自动醒来，也不为定时汇报另建外部通知服务。无法恢复控制时提前说明，改用可控短任务，不能承诺无法保证的定时更新。

额度或模型权限错误可按已授权备用顺序切换；暂时性网络、限流或服务故障默认最多重试一次，遵守等待提示和剩余预算。切换前确认旧会话/进程已停止，核对已写文件、已执行请求和费用状态，再交接剩余工作；状态不明时先查明，不能双跑。候选耗尽报告阻塞，不循环回已失败候选。

证据冲突、未找到资料、账号门槛、低质量结论不当作模型服务故障。先补上下文、调整路径或拆分，再按已授权范围升级；不能用反复换模型获取期望答案。共享账号或计费请求失败后先核实结果，不能每个 agent 各自重发。

达到研究阶段目标、预算截止或用户取消时，主 agent 收拢产物并处理仍运行的任务：不再需要的实际停止，确认状态后更新台账；如果停止状态暂不能核实，明确报告，不宣称全部结束。交付时区分已核验、仅收到、未执行、取消和阻塞的子任务。
